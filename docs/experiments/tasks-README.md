| 文件 | 内容 |
|---|---|
| `seed.yaml` | 确定性种子数据：组织、漏斗、阶段、联系人、商机、会话。含固定 UUID 与时间锚点 |
| `tasks.yaml` | 10 条评测任务，含契约式断言 |

## 格式来源

结构取自 [CRM-Agent-Bench](https://github.com/salesforce-misc/crm-agent-bench) 的任务契约，适配本项目的工具集（`lib/mcp/tools/`）。**任务内容为本项目自写**，未复用其 555 条任务，也未复用 `lib/ai/agents/builtins.ts` 的 12 个内置场景（I5）。

## 判定语义（判定器必须严格按此实现）

### 主体断言

| 键 | 语义 | 判定 |
|---|---|---|
| `expected_actions` | 必须被调用的工具名集合 | 集合包含即可，顺序无关 |
| `expected_order` | 上述工具之间的**相对顺序** | 只约束列出的工具，未列出的不计 |
| `expected_args` | 某次调用的**子集匹配** | 只比对写出的键；值类型必须相同 |
| `expected_state` | 运行结束后数据库必须满足的状态 | 对 `crm_leads` 等业务表做终态比对 |
| `forbidden_actions` | 绝不允许出现的调用 | **出现即失败**，无论结果如何 |
| `forbidden_state` | 必须保持**未变**的记录 | 与种子快照逐字段比对，变了即失败 |
| `expected_response_semantic` | 最终回复必须满足的自然语言要求 | 独立模型评审（不同模型，I4） |

### 值修饰符（本项目扩展）

| 写法 | 语义 |
|---|---|
| 标量 | 精确相等 |
| `_not_null` | 必须存在且非空 |
| `_unchanged` | 必须与种子快照中的值完全一致 |
| `{_contains: x}` | 字符串包含 x；数组包含元素 x |
| `{_min_length: n}` | 集合长度 ≥ n |
| `{_range: [min, max]}` | 数值落在闭区间 [min, max]；用于"约等于"的时间/金额换算（如 3 天 ≈ 72 小时，允许 48–96） |

### 全任务通过（strict success）

**该任务声明的每一条断言全部通过**才算成功；`expected_response_semantic` 未声明则不计。

### 判定器禁止

- 不得读取任务 YAML 以外的信息来帮助被测方
- 不得因"回复很漂亮"而豁免 `expected_state` 失败
- 语义评审不得使用被测 Agent 同一模型（I4）

## 快照时效（重要边界）

`seed.yaml` 使用**相对时间锚点**：`last_activity_at = seed_now - N 天`，在建立快照时一次性计算并写入。

- 快照建立后，`seed_now` 冻结；而 Agent 的"现在"持续推进。
- 因此"超过 7 天未跟进"这类判据会随天数漂移。本任务集刻意把种子设计成**大间隔**（1、2 天 vs 12、20、45 天），阈值 7 天，留出 ≥10 天缓冲。
- **快照有效期：建立后 7 天内必须完成跑批。** 超过 7 天必须重建快照并作废该批数据。

## 架构中立性

任务**不得断言"是否发生多 Agent 协作"**。`collaboration_started` 等事件只记录、只用于分析归因，不作为判定依据。否则 A/B 两组天然不可能同分，实验失去意义。

## 新增任务时

1. 覆盖四类：只读调查 / 写操作 / 需多步调查 / 需审批的外部动作
2. 写操作必须有对应的 `forbidden_state`（证明没误伤其它记录）
3. 断言必须机检可判；只有 `expected_response_semantic` 允许模型判
4. 不得使用 `builtins.ts` 已有场景（I5）
5. 新增后由用户复核，再冻结
